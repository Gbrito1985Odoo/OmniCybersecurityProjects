
Actúa como un arquitecto de software senior y desarrolla una aplicación completa 
llamada "TraceLens" (paquete Python: tracelens), un analizador inteligente de 
trazas (logs/traces) con IA local, sistema de etiquetado y chat asistido por IA. 
La aplicación debe cumplir con TODOS los requisitos siguientes.

=====================================================================
CONTEXTO Y OBJETIVOS
=====================================================================
TraceLens analiza trazas en tiempo real y desde ficheros usando un LLM local 
(vía Ollama) para detectar errores, patrones anómalos, correlaciones y 
severidad, enriquece las trazas con etiquetas, permite filtrarlas con listas 
blancas/negras, genera informes automatizados y ofrece un chat conversacional 
(RAG) para consultar en lenguaje natural todo lo analizado. Todo el 
procesamiento es 100% local (sin llamadas a servicios externos).

=====================================================================
STACK TECNOLÓGICO
=====================================================================
- Python 3.11+
- FastAPI + Uvicorn (API REST + SSE para streaming)
- asyncio + asyncio.Queue para desacoplar ingesta y análisis
- Pydantic v2 (esquemas y validación)
- SQLite (por defecto) con opción a PostgreSQL vía SQLAlchemy 2.x async
- ChromaDB o FAISS local (vector store para RAG)
- Ollama como runtime de LLM local (endpoint configurable, por defecto 
  http://localhost:11434); modelos sugeridos: llama3.2:3b o qwen2.5:7b para 
  generación, nomic-embed-text para embeddings
- sentence-transformers como alternativa de embeddings locales
- APScheduler (informes programados)
- Jinja2 (plantillas de informes)
- Typer/Click (CLI)
- pytest + pytest-asyncio (tests)
- Dockerfile + docker-compose (incluye servicio Ollama)
- Frontend ligero con HTMX + Alpine.js o React (chat con streaming SSE)

2. INGESTA DE TRAZAS
=====================================================================
a) TIEMPO REAL:
   - tail -f sobre ficheros (soporta rotación logrotate, múltiples ficheros)
   - Endpoints: UDP/TCP tipo syslog y HTTP POST /ingest
   - Buffer configurable y backpressure
   - Checkpoint de offsets para reanudar tras reinicio

b) FICHEROS:
   - Lectura de fichero individual o directorio completo
   - Formatos: JSON lines, texto plano, syslog (RFC5424/3164), CSV, regex 
     personalizada configurable
   - Carga paralela con barra de progreso y reanudación por checkpoint

=====================================================================
3. MOTOR DE ANÁLISIS CON IA LOCAL
=====================================================================
Cliente Ollama configurable (endpoint + modelo). El motor debe:
- Analizar traza individual o ventana temporal y detectar:
  * errores y excepciones
  * patrones anómalos (picos, secuencias, repeticiones)
  * correlaciones entre eventos
  * indicadores de seguridad (auth failures, inyecciones, scans)
  * degradación de rendimiento
- Clasificar severidad: info | warning | error | critical
- Extraer entidades: IPs, usuarios, endpoints, códigos HTTP, duraciones
- Generar resumen semántico por bloque de trazas
- Embeddings locales para agrupar trazas similares y detectar clusters
- Prompt templates versionados en /prompts
- Cache de resultados de IA (hash de entrada -> salida) para no reprocesar
- Reintentos con backoff ante fallos del LLM

=====================================================================
4. SISTEMA DE ETIQUETADO (LABELS)
=====================================================================
Sistema transversal de etiquetas que enriquece las trazas:
- Etiquetas AUTOMÁTICAS generadas por la IA (ej. error_db, auth_failure, 
  timeout, pico_trafico)
- Etiquetas MANUALES creadas por el usuario vía UI/API
- Etiquetas DERIVADAS de reglas de filtrado
- Jerarquía categoría > subetiqueta y vocabulario controlado
- Persistencia en BD con índices para búsqueda rápida
- API CRUD: crear, listar, renombrar, fusionar, eliminar
- Filtros por etiqueta combinables con listas blancas/negras
- Estadísticas por etiqueta: frecuencia, evolución temporal, top N
- Las etiquetas deben estar disponibles en:
  * informes generados
  * consultas del chat
  * búsquedas y dashboards
- La IA puede SUGERIR nuevas etiquetas al detectar patrones no catalogados 
  (con aprobación opcional del usuario)

=====================================================================
5. CHAT ASISTIDO POR IA (RAG)
=====================================================================
Asistente conversacional integrado para consultar las trazas en lenguaje 
natural.

a) CAPACIDADES:
   - Preguntas sobre errores concretos
   - Consultas de agregación ("top 10 IPs con más fallos esta semana")
   - Explicaciones ("¿por qué se marcó esta traza como crítica?")
   - Correlaciones ("¿qué ocurrió antes del pico de latencia?")
   - Comparaciones temporales
   - Preguntas sobre etiquetas
   - Generar informes ad-hoc desde el chat
   - Sugerir reglas de filtrado a partir de la conversación

b) PIPELINE RAG:
   - Indexación en VectorStore de: trazas normalizadas, resúmenes IA, 
     etiquetas y metadatos (severidad, timestamps, servicio)
   - Retrieval top-k por similitud + filtros de metadatos (fecha, servicio, 
     etiqueta, severidad)
   - Construcción de contexto acotado (respetar límite del modelo local, 
     configurable)
   - Generación con citación de trazas fuente (IDs clicables en la UI)
   - Function-calling / tool-use: el LLM puede invocar herramientas 
     estructuradas (query_traces, count_by_label, top_ips, etc.)

c) SESIONES:
   - Historial por sesión persistido y recuperable
   - Streaming de respuesta token a token vía SSE

d) UI DE CHAT:
   - Interfaz web de chat (panel lateral o vista dedicada)
   - Renderizado markdown, tablas y bloques de código
   - Enlaces clicables a trazas citadas
   - Botones rápidos: "generar informe de esto", "crear etiqueta", 
     "añadir a lista negra"
   - Selector de contexto previo a preguntar: rango fechas, servicio, 
     etiqueta, severidad

e) LÍMITES Y SEGURIDAD:
   - Contexto máximo configurable
   - Rate limiting y cuotas por sesión
   - 100% local (sin envío de datos fuera)
   - Registro de conversaciones para auditoría (configurable)

=====================================================================
6. FILTRADO: LISTAS BLANCAS Y NEGRAS
=====================================================================
Motor de reglas configurable:
- Reglas por campo: regex, match exacto, contains, comparadores numéricos
- Combinación lógica AND/OR, prioridades
- Lista blanca (ignorar coincidencias) y lista negra (forzar análisis/alerta)
- Reglas por origen: fichero, host, servicio
- Gestión dinámica vía API y UI (CRUD) con recarga en caliente
- Persistencia en SQLite o YAML/JSON
- Modo dry-run contra trazas históricas
- Métricas por regla: cuántas trazas ha filtrado
